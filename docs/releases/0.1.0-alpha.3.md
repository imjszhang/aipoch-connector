- Fix #1: MCP initialization and runtime status use the same package manifest product version. MCP protocol version remains unchanged.
- Fix #2: fixed-file acquisition replay ignores source observation timestamps and JSON property order. A completed operation returns its original durable result after fresh CLI resolution and runtime restart. Different stable inputs still conflict; pending operations never execute again automatically.

Only `source.resolvedAt` and `source.repositoryLicenseObservation.observedAt` are omitted from identity comparison; other source changes remain conflicts.
- Return the specific GitHub acquisition error (including `destination_exists`) through the CLI instead of masking it as a generic internal error.

## Upgrade and recovery

Stop the old core and back up its database and sidecars before upgrading. Schema 1 is upgraded transactionally to schema 2 without rewriting receipts, associations or existing operation results. Alpha.1/alpha.2 cannot open schema 2; rollback requires the pre-upgrade backup, and would not include subsequent records. Do not lower the schema marker or discard new records.

Old acquisitions have no full saved input. They remain queryable using `operations show ID`. Only an exact match of their original input digest can return their old result; a freshly resolved old CLI operation normally returns `legacy_operation_unverifiable`. Inspect the original operation and destination; never choose a new ID automatically. This release does not reconstruct missing old evidence or retroactively repair old operation IDs.
