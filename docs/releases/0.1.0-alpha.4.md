# 0.1.0-alpha.4

HTTP pages on `localhost`, `127.0.0.1` and `[::1]` can now request a Connector pairing at any port by default, alongside the exact production origin `https://aipoch.network`. A successful request still requires the user's local approval and a ready authenticated host. Sessions remain bound to the complete origin; a different hostname or port cannot reuse them.

## Configuration and upgrade

- `allowLoopbackHttp` defaults to true for new configurations and older files without this field. Reading old configuration preserves its bytes and explicit origin list.
- `setup --loopback-http deny` disables implicit local HTTP permission; `allow` restores it. Setup still requires the user-selected running host. Explicit false is retained by subsequent setup.
- Explicit `origins` remain additive even with the policy disabled. To deny all local websites, also remove any local entries you previously added explicitly.
- To retain only the original origin list during upgrade, stop the old core and set `"allowLoopbackHttp": false` in owner configuration before starting this version.
- Effective-policy changes use authenticated, scoped runtime restart. Pairings/sessions expire; durable inbox, associations and operation records remain. Database schema stays 2.

This is not a wildcard CORS rule. LAN IPs, hostname suffixes, other loopback aliases, malformed origins and local HTTPS are not implicitly allowed. `[::1]` permits an IPv6 website origin; Connector continues listening only at `127.0.0.1`. Browser/Node restricted-port policies still apply.

The catalog address and public canonical reference location remain owner-configured/default production values. Use `--catalog-url` for a local preview's matching snapshot; the visiting webpage cannot select a backend fetch target or bypass exact review validation.
