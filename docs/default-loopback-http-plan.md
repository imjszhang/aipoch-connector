# 默认允许本地 HTTP 网站：实施与验收计划

状态：实现与本地验收通过，待远端检查、合并及发布。用户已授权在 PR #4 实现、验收、合并并同步；本文保留原计划与验收范围，实际结果记录于 [alpha.4 验收记录](verification/alpha4-loopback.md)。

用户决定（2026-09-14）：保留 `https://aipoch.network`，默认允许
`localhost`、`127.0.0.1`、`[::1]` 的任意 HTTP 端口。此前建议的固定 4193 端口方案不采用。
基线：`74c066904326d2d5a21e5c9d949d31e20238c20c`，已发布 alpha.3。

## 1. 完成后的用户行为

- 新安装以及没有显式关闭本地 HTTP 许可的旧配置，无需逐端口执行 `setup --origin`，即可由上述三个主机名的 HTTP 页面发起配对。
- 无显式端口的 HTTP origin（默认 80）也包括在内；浏览器实际发送的 origin 必须是规范形式。
- 页面获准发起配对不等于已授权：仍需用户核对来源和验证码，再建立绑定到精确 origin 与宿主实例的限时会话。
- `http://localhost:3000` 与 `http://localhost:3001`、`http://127.0.0.1:3000` 彼此不是同一会话来源，不能交换配对或会话凭证。
- 网站不能读取 owner 管理接口、宿主/GitHub 凭据或全部本地项目；收到引用仍不代表获取文件或执行研究。

## 2. 默认策略与精确边界

新增配置字段 `allowLoopbackHttp?: boolean`。有效默认值为 `true`，明确的 `false` 关闭隐式本地 HTTP 许可。
保留现有 `origins: string[]` 精确白名单，默认值仍含 `https://aipoch.network`。

最终允许条件：**精确白名单匹配，或者开启本地 HTTP 策略且匹配严格本地 origin**。
关闭隐式策略不删除白名单中显式添加的本地地址。用户若需要完全禁用本地来源，也应移除自己显式添加的对应项；文档须说明两者关系。

| Origin 示例 | 默认策略预期 |
| --- | --- |
| `https://aipoch.network` | 允许 |
| `http://localhost`、`http://localhost:3000`、`http://localhost:65535` | 允许 |
| `http://127.0.0.1:5173`、`http://[::1]:8080` | 允许 |
| 任意其他合法 HTTP 端口，包括随机预览端口 | 同一主机名条件下允许 |
| `https://localhost:3000` | 不由本地 HTTP 策略自动允许，可显式配置 HTTPS origin |
| `http://localhost.evil.example:3000`、`http://evil.localhost:3000`、`http://localhost.:3000` | 拒绝 |
| `http://127.0.0.2:3000`、`http://0.0.0.0:3000`、局域网 IP | 拒绝 |
| IPv4 映射 IPv6、整数/十六进制/缩写 IP 写法 | 拒绝非规范 origin，不扩大地址集合 |
| `null`、缺少 Origin、多个拼接 Origin、带路径/查询/片段/凭据的值 | 拒绝 |
| 未显式配置的公网 HTTP/HTTPS、生产站点子域名 | 拒绝 |

实现必须验证 URL 解析成功、`url.origin === 原始值`、协议严格为 `http:`、hostname 严格属于三个名称；不做字符串前缀/后缀匹配，不进行 DNS 解析来扩展许可。
HTTP 默认端口等 URL 序列化差异按浏览器规范 origin 处理，不把非规范请求头宽松归一化后放行。合法端口采用 URL 解析规则；不提供通配符 origin 字符串。

“任意端口”指 Connector 的来源许可策略。浏览器与 Node 自身的受限端口规则仍适用，不能绕过；已有 4190 目录请求失败记录保留。
`[::1]` 是网站来源许可，不代表 Connector 开始监听 IPv6：服务仍只监听 `127.0.0.1`，浏览器适配器仍访问 `http://127.0.0.1:47821`。

## 3. 配置、升级与运行时生命周期

1. 在 `src/runtime.ts` 的 `Configuration` 增加字段，缺失时读取为 `true`；只接受布尔值，字符串、数字和 null 均报错。
2. 新配置明确写出有效值；旧配置读取时不改写文件。旧 `origins` 列表、端口、宿主 profile、catalog URL 和 GitHub App 设置均保留。
3. 新增 CLI `setup --loopback-http allow|deny`，映射到布尔配置；保留 `--origin` 的精确追加能力。无参数 setup 保留显式 `false`，不能重新开启。
4. 升级后的缺省行为会扩展旧配置的有效本地许可，这是本次用户指定的默认改变；发布说明必须明确。希望保留原来仅白名单策略的用户，可在启动新版本前将配置字段设为 `false`。
5. `configurationDigest` 纳入有效值：缺失与 true 等价，true/false 不等价；自定义显式 false 必须在读取、保存和再次 setup 后保持。
6. 修改策略时沿用已认证运行时的安全重启流程，验证新 identity/config digest；旧会话/配对失效，收件箱、关联和操作记录保持。
7. 旧版本不会识别新增隐式许可，仍按精确白名单工作。无需数据库迁移，schema 保持 2。不得把每个已连接端口永久写入 origins。

## 4. 代码实施拆分

### A. 统一来源判定

新增小型来源策略模块，例如 `src/origin-policy.ts`，承载 hostname 集合、严格 origin 判定及有效策略解析。
不要修改全局 URL 安全校验器以免扩大 GitHub、catalog 或宿主凭据请求范围。

`src/bridge.ts` 接收显式策略选项，用统一判定替代 `/v1/` 中单一 `origins.includes(origin)`。
运行时必须传入解析后的策略。直接构造 bridge 的旧测试/调用未传新选项时，保持仅精确白名单，以免既有受限测试夹具被隐式扩大；产品默认由运行时显式提供。

CORS 仅在成功判定后回显当前精确 origin，继续带 `Vary: Origin`，不输出 `*`。
预检和实际请求共用同一准入判定；`/admin/` 不采用本地来源许可，继续拒绝带 Origin 的浏览器请求。

### B. 配置与 CLI

修改 `src/runtime.ts`、`src/cli.ts`，同步 help、配置验证、有效默认值、摘要和重启传参。
错误发生在保存配置前；无效 flag 值不能损坏旧文件。
若 `Configuration` 在测试/包装代码中构造，核查调用点并按测试意图显式选择策略。

### C. 本地网页与目录校验

保持三个独立概念：浏览器来源、可信 catalog 地址、引用的公开规范地址。
默认 catalog 仍是 `https://aipoch.network/catalog/v1/manifest.json`，默认 `public_location` 仍属于生产公开站点。
本地预览可以发送这些生产规范链接；已有本地联调采用过这一模式。

本地预览使用不同 snapshot 时，仍需通过 owner 的 `--catalog-url` 指定匹配目录；不根据来访 Origin 自动切换 catalog，不允许网站指定后端读取目标。
补充本地来源提交生产规范引用的通过用例，以及仅替换 `public_location`、篡改 snapshot/来源/许可仍被拒绝的用例。

本 PR 的后续实现不把任意自定义发布域名或 HTTP `public_location` 加入完整引用协议。若某个本地前端实际生成本地域名的 `public_location`，必须报告这个不兼容并使用生产规范链接构建验证；不能将配对通过当作引用接收通过。泛化发布基址需独立设计，不能以跳过精确内容校验实现。

## 6. 真实浏览器验收

自动化通过后，对真实本地 Network real-mode 预览和已由用户启动的宿主进行独立验收：

1. 从全新、默认 Connector 配置开始，先在 localhost 的一个端口访问，再在另一个端口访问，均不加 `--origin`。
2. 验证发起配对、用户亲自比较来源/验证码、批准、新会话 ready、分别审核后发送引用、可见回执与 durable SHA 一致。
3. 覆盖 127.0.0.1；IPv6 回环网站需实际可访问时才记录 [::1] 浏览器通过，否则只记录已通过的协议夹具范围，不能声称 IPv6 实机支持。
4. 跨端口使用原会话失败；显式关闭策略并重启后，新本地连接被拒绝，历史回执仍可由 owner 查询。
5. 生产站点连接能力不回归；记录实际浏览器/OS/宿主/Connector 版本、预览端口、catalog snapshot 和回执摘要，不记录凭据或确认票据。

不会启动宿主、代替用户点击产品确认或绕过浏览器本地网络权限。缺少真实环境或用户确认时，记录具体待验收项，不把自动化夹具结果升级为真实浏览器通过。
